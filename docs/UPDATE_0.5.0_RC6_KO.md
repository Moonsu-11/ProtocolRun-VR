# ProtocolRun-VR 0.5.0 RC6 업데이트

RC6는 Gemini 연결 자체가 아니라 실제 헤드셋 진단 입력과 증거 수명 주기에서 확인된 실패를 수정한다.

## 실측 원인

- RC5의 독립 Google ADK Function Calling 검사는 실제 `propose_recovery`를 7.76초 만에 깨끗하게 완료했다.
- 이후 실제 Quest 세션 JSON에는 CUBE_B의 서로 다른 유효 실패가 시퀀스 88, 93, 97에 기록됐다.
- 첫 번째와 두 번째 운영 진단 호출은 각각 정확히 60초에 `TimeoutError`로 종료됐다.
- 세 번째 호출은 마지막 실패 약 129초 뒤 시작됐다. 당시 일반 증거 유효시간 90초를 넘겨 서버가 모델에 보낼 검증 증거가 없어졌고, Gemini/Firewall은 안전하게 `manual_review`를 선택했다.
- 따라서 참가자의 핀치 부족이나 B 설정 오류가 원인이 아니었다.

## RC6 변경

- Gemini 입력은 프로토콜 핵심 필드, B의 등록 기준값, 서버의 결정 결과, 검증된 실패 3개로 제한한다.
- 반복 텔레메트리, 머리·손 위치/회전, 참가자 자유 문장은 모델 입력에서 제외한다.
- 세 번째 실패가 서버의 모든 기술 조건을 통과하는 순간 정확한 실패 이벤트 ID 3개를 진단 주기에 고정한다.
- 이 고정은 최대 240초 후 자동 만료된다. 각 재시도에서도 기준값, 시도-실패 연결, 기술 조건, 이후 정상 관찰 여부를 다시 검사한다.
- Gemini 호출 제한은 기존과 동일한 60초다. 무작정 제한시간을 늘리지 않았다.
- 감사 기록에는 원본 진단 스냅샷 크기와 실제 모델 입력 크기를 남겨 압축 여부를 확인할 수 있다.

## 자동 검증

- 백엔드 테스트 53개 통과.
- 130초 지연 뒤에도 같은 진단 주기의 검증된 3개 실패가 유지되는 회귀 테스트 통과.
- 240초가 지나면 고정 증거가 만료되는 테스트 통과.
- 모델 프롬프트에서 원시 위치·회전·참가자 문장이 제외되는 테스트 통과.

## 아직 필요한 실환경 합격

RC6 ZIP 적용 후 `VERIFY_GEMINI_TOOL_WINDOWS.bat`가 실제 Google ADK Tool 호출을 완료해야 한다. 이 검사는 운영 형태의 큰 입력을 만들지만 실제 모델에는 압축된 서버 검증 증거만 보낸다. 이 검사가 통과한 뒤에만 새 Quest 세션으로 B 복원 폐쇄 루프를 다시 확인한다.
